# 地球世界推演模块开发交接

## 1. 范围与权威边界

本模块属于道渊小手机 V1.2 源码，不是独立外挂。附属世界书提供世界设定和 EJS 按需路由；小手机的本地状态机是已确认世界状态的唯一权威；独立 API 只能给出候选动作；正文 AI 只接收经过裁决的状态摘要。

三条不可混淆的链：

```text
世界书 JSON → 内置种子 → 安装/挂载/按需 getwi
聊天变量 → schema/reducer → 小手机展示与持久化
最近 5 条 AI 回复 + 世界书 → 推演 API → 校验/纠正 → reducer 提交 → 正文注入
```

不要把世界书条目开关、推演账本、正文注入当成同一层。普通条目在世界书 UI 中保持灰色关闭；10 条 EJS 路由用装饰器参与生成并动态 `getwi`。这既避免 187 条常驻，又让正文模型能拿到当前场景需要的设定。

## 3. 数据与运行契约

- 聊天状态键：`daoyuan_earth_simulation_v1`，不得写入原版 `stat_data`。
- API 设置键：浏览器本地设置；密钥不得进入聊天变量、世界书、提示词或导出 JSON。
- 正文注入 ID：`daoyuan_world_context`。注入当前日期、时间比例、阶段、发生变化的区域/势力和活跃事件；角色知识仍受信息渠道限制。
- 推演上下文：最近 5 条 assistant 回复，不把 user 输入计为层数；世界书读取的是当前挂载书内容，而不是仅靠内置提示词猜设定。
- 时间语义：动作里的 `days` 是玄天界基准日；本地 reducer 按玩家比例换算地球日。慢速比例用 `earthDayRemainder` 累积余数。
- 输出语义：模型返回受限动作；未知字段或非法枚举先触发一次纠正，第二次仍非法则拒绝整批，不做半提交。
- 清空语义：删除本聊天全部推演状态并重新从默认开局初始化；UI 必须二次确认，不删除世界书和 API 配置。

## 4. 世界书结构与兼容性

- 总计 187 条：1 条原生常驻的“双界基准监控”、10 条 EJS 路由、176 条普通设定/人物/城市资料。
- 10 条 EJS 路由内容必须以 `@@generate_before\n@@always_enabled\n` 开头。
- EJS 条目显示灰色关闭是正式设计，不应手工全开。`@@always_enabled` 解决 ST-Prompt-Template 新旧启用语义差异。
- 路由按上下文限量：组织 4、玄天势力 3、人物接口 3、NPC 4、城市 3；不得把全部条目一次性打印。
- 已存在的同名世界书只补缺失或在用户明确点击“更新内置规则与 EJS”时更新内置特殊条目；不能静默覆盖用户正文。

## 6. 项目工具适配表

所有命令在 `app/` 执行。测试命令只读源码/产物；`build` 写 `app/dist/道渊功能前端.js`；`package:v12-test` 写 V1.2 测试候选 JSON。写入前应确认目标路径和工作树。

| 能力 | 命令 | 输出/成功标准 |
| --- | --- | --- |
| 世界书种子校验 | `pnpm test:earth-worldbook` | 187 条、装饰器、哈希和种子一致 |
| 安装管理器校验 | `pnpm test:earth-worldbook-manager` | 创建/挂载/补缺失/拒绝危险覆盖通过 |
| 状态与 reducer | `pnpm test:earth-simulation` | schema、默认开局、比例推进、容量边界通过 |
| 推演运行时 | `pnpm test:earth-runtime` | 5 条 assistant 上下文、候选解析与动作限制通过 |
| UI 绑定 | `pnpm test:earth-ui` | 无预览假数据、详情/分类/清空操作绑定通过 |
| 正文注入 | `pnpm test:prompt-injection` | 固定注入及地球账本摘要通过 |
| 类型检查 | `pnpm typecheck` | 退出码 0 |
| 构建 | `pnpm build` | 生成 `dist/道渊功能前端.js` |
| 测试包 | `pnpm package:v12-test` | 生成 `dist/道渊小手机V1.2测试.json` |

项目没有为这些命令提供 dry-run。打包会覆盖同名测试产物；失败后的恢复方式是保留权威源码，重新执行构建与打包，而不是手工编辑产物。

## 7. 接手时先做什么

1. 读根目录 `NEXT.md` 和本文件，不要先改代码。
2. `git status --short`，确认未提交文件仍在；不要清理、重置或覆盖。
3. 复算测试包与世界书 SHA-256，确认测试对象没有漂移。
4. 若目标是继续真机验收，按 `验收记录.md` 的下一门槛操作；若目标是修改功能，先更新 `创作规划.yaml` 与对应契约，再改最小源码和测试。
5. 只有用户明确授权“正式发布”后，才允许决定正式产物名、写入 `releases/`、提交、推送或发布。
