# 灵力复苏地球推演脚本：小手机整合构建流程

> 当前实施状态（2026-08-27）：V1.2 测试候选已完成并进入真实酒馆门控。跨对话进度只以根目录 `NEXT.md` 为准；实现地图见 `开发交接.md`，分门槛证据见 `验收记录.md`。本文件保留设计约束与构建流程，不再承担实时进度记录。

## 0. 任务定义

在现有“道渊小手机”源码中新增“地球推演”模块。模块负责安装和挂载《灵力复苏地球附属世界书》、维护每个聊天独立的双界世界状态、低频调用独立API生成候选演化、校验并提交状态补丁，再向世界书EJS提供本轮允许装载清单。

这不是新的外挂酒馆助手脚本。最终产物必须继续由小手机现有Vite构建和`package-candidate.mjs`打包，整合进同一个道渊小手机导入JSON。

## 2. 不可突破的红线

1. 不覆盖道渊主世界书。
2. 不覆盖用户已修改的同名附属世界书正文。
3. 不在启动期根据空快照整本回写世界书。
4. 不把API密钥写进聊天变量、MVU、世界书、提示词或导出JSON。
5. 独立API只提出候选补丁；本地脚本是已确认状态唯一权威。
6. API不得替`<user>`生成行动、台词、身份、情绪、关系选择或不可逆决定。
7. 重抽、重生成、回滚、失败回复和中止回复不得重复推进。
8. 对话轮数不等于世界天数；只有正文明确发生时间流逝时才推进日期。
9. 地球与玄天界时间默认1:1；V1.2 起允许玩家选择受控预设比例，实际日期、推演提示词、正文注入与界面必须使用同一比例。
10. 相交秘境和虫群通道分别维护；控制秘境不能关闭虫群通道。
11. 开局必须是复苏刚开始、学校筹建、虫群零星迹象、双界尚未正式接触。
12. 不把候选未来事迹提前写成开局已经发生。

## 4. 世界书安装与挂载

### 4.1 构建种子

以`灵力复苏地球附属世界书/灵力复苏地球附属世界书.json`为唯一构建输入，新增构建脚本将其转换为小手机可内置的种子：

```text
app/src/dlc/seeds/lingLiFuSuEarth.json
```

推荐身份：

- 稳定ID：`ling_li_fu_su_earth`
- 推荐世界书名：`灵力复苏地球附属世界书`
- 显示名：`灵力复苏地球`
- 类型：独立附属世界书

### 4.2 不直接套用现有DLC自动开关

现有`ExpansionManager.desiredState()`只支持境界进程、百花谷地点、洛阳地点和蜀山混合模式。地球世界书的普通内容条目由EJS动态`getwi`读取，不应被现有逻辑整本反复启停。

可以复用：

- 世界书发现
- 同名/别名诊断
- 创建缺失世界书
- 只补缺失条目
- 挂载到当前角色`additional`
- 空快照拒绝覆盖
- 编辑器刷新

不得复用：

- 四本旧DLC的`desiredState()`分支
- 每次状态变化整本切换条目启停

建议为地球世界书新增安装类型`simulation-routed`，或由`EarthSimulationManager`调用只读/安装能力。若扩展`DlcId`，必须补齐所有类型、默认设置、UI和测试，不得用类型断言掩盖遗漏。

### 4.3 安装策略

- 不存在：用户点击后创建。
- 已存在且完整：直接使用，不覆盖正文。
- 已存在但缺条目：只允许“补回缺失条目”。
- 有重名条目、多个候选世界书或读取为空：停止自动修改并显示诊断。
- 挂载时只向当前角色`additional`追加，不改变`primary`。

## 5. 状态模型

在`schema.ts`使用Zod定义严格状态。建议顶层结构：

```ts
interface EarthSimulationState {
  schemaVersion: 1;
  chatId: string;
  sequence: number;
  lastCommittedFingerprint: string;
  openingDate: string;
  earthDate: string;
  xuantianDate: string;
  revivalYear: number;
  revivalStage: '复苏初现' | '局部复苏' | '全球公开' | '全面超凡化';
  contactStage: '互不知情' | '少数知情' | '势力接触' | '公开交流';
  secretRealmStage: '未激活' | '信息联系' | '人员携物通行' | '制度化往来';
  swarmEarthStage: '零星迹象' | '局部虫巢' | '区域战争' | '双界同时入侵' | '界域危机';
  swarmXuantianStage: '零星迹象' | '局部虫巢' | '区域战争' | '双界同时入侵' | '界域危机';
  regions: Record<string, RegionState>;
  factions: Record<string, FactionState>;
  schools: Record<string, SchoolState>;
  npcs: Record<string, NpcState>;
  cities: Record<string, CityState>;
  events: SimulationEvent[];
  checkpoints: CheckpointMeta[];
  diagnostics: DiagnosticEntry[];
}
```

状态数组必须有限制：

- 活跃事件最多20项。
- 已关闭事件最多保留50项摘要。
- 诊断最多保留80项。
- 检查点最多保留20个。
- 已处理消息指纹最多保留200个。

人物、城市、势力使用稳定ID，不以显示名称作为唯一数据库主键。显示名可以以后修改，稳定ID不可变。

## 6. 开局初始化

首次在某聊天启用时创建状态：

- `openingDate`：启用当日现实公历日期。
- `earthDate`与`xuantianDate`：开局等于`openingDate`；之后按玩家当前时间比例分别推进。
- `revivalYear`：0。
- `revivalStage`：复苏初现。
- `contactStage`：互不知情。
- `secretRealmStage`：未激活。
- 地球、玄天界虫灾：零星迹象。
- 第一所学校：筹备启动，不是成熟大学。
- 相交秘境四个功能区：不存在/未建立。
- 72名人物载入“开局身份”；未来事迹不得写入已完成事件。

初始化必须幂等。重复打开小手机、刷新页面或切回聊天不得重建状态。

## 7. 每聊天持久化

### 7.1 权威状态

优先复用`ChatVariableRepository`，使用独立键：

```text
daoyuan_earth_simulation_v1
```

它保存已确认世界状态和最小检查点元数据，随聊天隔离。不要写入`stat_data`，避免污染原版MVU结构。

### 7.2 本地设置

API设置保存在宿主窗口`localStorage`：

```text
daoyuan_earth_simulation_api_settings_v1
```

只保存：启用状态、API地址、密钥、模型、温度、超时、自动推演间隔、单次最大世界日。

### 7.3 运行日志

长诊断、原始失败响应摘要和可选检查点正文使用IndexedDB或有容量限制的本地存储；聊天变量只保留可迁移的确认状态和短摘要。

## 8. 独立API实现

复用`ApiService`和`openaiProtocol.ts`，不要复制另一套直连/代理兼容代码。新增独立的`EarthSimulationApiSettingsSchema`，不得与仙网、玉简、绝色榜或万宝商行共享密钥和配置。

推荐默认值：

- 默认关闭自动推演。
- 温度：0.2至0.4。
- 最大输出：4096。
- 超时：120秒。
- 普通单次最大世界时间：30日，但实际可为0日。
- 只接受严格JSON。

API请求只发送：当前确认状态摘要、最近确认事实、未决压力、允许变化范围、禁止修改字段、父检查点、序号和稳定随机种子。不要发送完整聊天记录。

API响应必须通过Zod解析。禁止用正则从散文中猜JSON；若支持去除Markdown代码围栏，只能剥离单一完整围栏后再做严格解析。

## 9. 补丁裁决

响应采用白名单补丁，不接受任意JSON Patch路径。至少按以下顺序校验：

1. `schemaVersion`。
2. `simulationId`、序号、聊天ID和父检查点。
3. 请求指纹未提交过。
4. 补丁路径在白名单。
5. `from`与当前值一致。
6. 地球与玄天界日期按当前玩家时间比例推进，默认1:1，慢速比例必须累计余数而不是永久丢弃小数日。
7. 单次经过时间和阶段跨度未超限。
8. 不修改玩家状态、行动、台词、关系选择和身份。
9. 不让秘境未激活时出现驻留区、研究区或交易区。
10. 不让手机在秘境激活前恢复地球信号。
11. 不让虫群通道随秘境关闭而消失。
12. 在状态副本应用全部补丁并运行不变量检查。
13. 全部通过后原子提交；任一失败整批拒绝。

## 10. 推进调度

完整参考世界引擎的“正向轮次＋阶段事件”模式，但世界日期单独判断。

### 10.1 有效正向推进

只有宿主确认生成完成、聊天未切换、楼层仍存在、消息指纹与当前楼层一致时，才累计资格。

以下情况不累计：

- 重抽同一楼层。
- 编辑后重生成尚未确认。
- 删除/回滚。
- 生成失败、中止或空响应。
- 仅打开小手机、刷新状态或查看诊断。

### 10.2 调用检查点

满足任一条件才考虑调用API：

- 达到用户配置的有效回复间隔。
- 正文明示经过数日、数月或数年。
- 玩家重大行动已经在正文落定。
- 活跃事件到达阶段检查点。
- 用户手动点击“立即推演”。

即使达到调用条件，如果没有新的确认事实和时间流逝，也允许返回“无需推演”而不调用API。

### 10.3 事件阶段

建议统一阶段：

- 冲突类：迹象→发酵→逼近→爆发→收束。
- 建设类：提议→筹备→执行→关键→完成/失败。
- 调查类：线索→验证→锁定→揭露→结案/悬置。

普通推演最多让一个事件前进一个阶段。双界正式接触、秘境激活、虫群双界同时入侵属于高等级跃迁，需要明确前置事实。

## 11. 世界书EJS路由投影

`routerProjection.ts`从确认状态生成最小路由快照：

```ts
interface EarthRouterProjection {
  current_world: string;
  region: string;
  phase: string;
  swarm_threat: string;
  allowed_countries: string[];
  allowed_schools: string[];
  allowed_organizations: string[];
  allowed_sects: string[];
  allowed_characters: string[];
  allowed_npcs: string[];
  allowed_cities: string[];
  allowed_modules: string[];
  router_ready: boolean;
  worldbook_name: '灵力复苏地球附属世界书';
}
```

必须在真实SillyTavern/Tavern Helper/ST-Prompt-Template版本中探测这些值应写入哪种`local`变量接口，确保世界书EJS中的`getvar('daoyuan_earth.*', { scope: 'local' })`能够读到。

如果现有小手机只能写聊天变量而不能写ST-Prompt-Template local变量：

1. 不要假装路由已经成功。
2. 显示能力缺失诊断。
3. 保持`router_ready=false`。
4. 后续选择新增受控提示词注入适配器或调整EJS变量读取协议，但必须单独验证，不能静默混用MVU。

单轮上限：

- 国家/学校按现有路由限制。
- 地球组织最多4个。
- 玄天界势力策略最多3个。
- 原版人物接口最多3人。
- 地球关键NPC最多4人。
- 城市节点最多3个。

正式发布时，EJS路由采用`@@generate_before`与`@@always_enabled`组合。这样无论ST-Prompt-Template使用旧版“禁用特殊条目才执行”的兼容模式，还是新版启用语义，路由入口都会执行；普通资料条目仍保持关闭，只通过`getwi`按场景取用，禁止一次性向正文模型注入全部世界书。

## 14. 失败策略

- API断网/超时：保持最后确认状态，不生成重大事件。
- JSON非法：整批拒绝，保存截断诊断，不注入原始响应。
- 响应过期：拒绝。
- 重复指纹：忽略。
- 世界书未安装或未挂载：可维护状态，但`router_ready=false`并提示无法路由。
- EJS/getwi能力缺失：不启用批量条目，不改为常驻全开。
- 世界书瞬时空读：禁止写回。
- 用户切换聊天：中止或隔离旧请求，重新载入新聊天状态。
- 费用上限触发：暂停自动API，保留手动推演和诊断。

## 15. 自动化验收

### 15.1 世界书

- 内置种子条目数与源JSON一致。
- 条目名无重复。
- 只创建缺失世界书。
- 只补缺失条目，不覆盖修改正文。
- 挂载只改变`additional`。
- 空快照拒绝写回。

### 15.2 状态机

- 新聊天初始化一次。
- 刷新不重复初始化。
- 地球与玄天界日期永远相等。
- 普通事件单次最多前进一阶段。
- 秘境未激活时四区不能建成。
- 两界虫灾状态互相独立。
- 关闭秘境不改变虫群通道。

### 15.3 重抽与聊天隔离

- 同一楼层重抽只保留最终确认分支。
- 回滚撤销对应推演，不继续累计旧分支。
- 聊天A的延迟API响应不能写入聊天B。
- 重复响应不会重复提交。

### 15.4 API

- 三种现有API模式兼容。
- 超时、中止、非法JSON、未知字段和越权路径全部安全失败。
- API密钥不出现在聊天变量、导出包、日志和UI上下文。

### 15.5 UI

- 390×844布局通过。
- 深色原生控件各状态通过。
- 长模型名不撑破布局。
- 保存、刷新、获取模型、立即推演均有忙碌和失败反馈。

## 16. 构建与交付顺序

1. 冻结当前小手机测试基线，不修改正式发布文件。
2. 将地球世界书生成结果转换为内置种子并做数量/哈希测试。
3. 实现Zod状态、默认值、不变量和纯reducer。
4. 实现每聊天持久化、指纹、检查点与回滚。
5. 实现独立API提示词、响应schema和候选补丁校验。
