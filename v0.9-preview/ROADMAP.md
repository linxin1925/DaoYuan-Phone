# 长期路线

## 评估 Vue 组件化重构

状态：长期待办，当前不实施。

道渊小手机目前采用 TypeScript、原生 DOM 与 CSS 实现。现阶段功能已经可以稳定构建和运行，不为了更换技术栈而整体重写。

当后续新增较多功能，并出现以下一种或多种情况时，再评估分阶段迁移 Vue：

- 手机应用、设置页面和弹窗数量明显增加。
- 页面状态、草稿状态及跨页面联动难以继续由手工 DOM 更新维护。
- 数据刷新频繁引发整页重绘、焦点丢失、滚动位置丢失等问题。
- `renderUi.ts` 的修改冲突和回归风险持续升高。
- 需要建立可复用组件、统一表单校验或更细粒度的响应式更新。

若启动迁移，应遵循以下边界：

1. 保持酒馆助手正式 JSON 的导入方式与运行入口不变。
2. 保持 Tavern Helper、MVU、世界书和聊天变量协议不变。
3. 按应用逐个迁移，不一次性重写全部界面。
4. 优先迁移状态复杂且仍在频繁扩展的页面。
5. 每个阶段都重新验证桌面、iPhone、Android、重 Roll、聊天切换及输入焦点。
6. Vue 运行时必须内联进正式 JSON，不增加玩家侧安装步骤。

在决定迁移前，可以先移除当前未使用的 Vue 运行时依赖；真正开始迁移时再恢复对应依赖和构建配置。
