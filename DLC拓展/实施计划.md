# 道渊 DLC 拓展管理 · 实施计划

> 状态：四本 DLC 已实现，正在进行原版兼容修订
> 建立日期：2026-08-20
> 正式源码：`app/`
> 原始材料：`道渊世界观剧情拓展/`

## 1. 目标、红线与验收

### 1.1 目标

在道渊自己的 Tavern Helper 常驻脚本中增加 DLC 拓展管理能力：

1. 脚本内置“万年仇怨、合欢宗扩展、洛阳扩展”三本世界书的首次安装副本；
2. 一键创建缺失的独立世界书，并检测它们是否挂载为当前角色的附属世界书；
3. 若目标运行时存在公开、稳定的角色附属世界书写入 API，则提供一键挂载；若不存在，则保留一次手动挂载门；
4. 不使用拓展自带的三个助手脚本，由道渊脚本统一监听 MVU、聊天和生成生命周期；
5. 根据地点、境界和用户开关启停条目，减少每轮提示词 token；
6. 酒馆中的独立世界书是运行时数据真源，允许用户手动更新、修改和替换；脚本不得在启动时覆盖用户内容。

### 1.2 红线

- 不覆盖、合并或改写道渊主世界书；
- 不导入、不执行拓展附带的助手脚本；
- 不把三本拓展注册成全局世界书；
- 不使用每秒轮询；
- 不为了“一键挂载”修改未验证的 SillyTavern 私有对象、私有 DOM 或内部存储；
- 不自动覆盖用户修改过的世界书正文；
- 不把用户开关、安装状态或版本信息写入 `stat_data`；
- 不新增模型调用，不增加额外生成轮次；
- 不把离线构建通过当作真实酒馆验收完成。

### 1.3 完成验收

- 三本拓展可由设置页一键安装，重复点击不会产生重复世界书或重复条目；
- 主世界书绑定与内容保持不变；
- 设置页能区分“未安装、已安装未挂载、已挂载、内容不兼容、用户修改版”；
- 当前运行时若支持公开附属绑定写入，一键挂载后能在角色绑定信息中复读确认；否则明确引导用户只手动挂载一次；
- 脚本启动、MVU 初始化、MVU 更新完成、聊天切换后，DLC 状态均可稳定收敛；
- 地点和境界未变化时不重复写世界书；
- 洛阳、百花谷离开对应地点后不再注入地点常驻内容；
- 万年仇怨只有当前最高剧情进程保持激活，降境界不回退已达进程；
- 三本世界书可被用户独立替换更新，脚本不会自动回滚正文；
- 通过离线自动检查，并完成真实 SillyTavern 中的安装、挂载、启停、更新、聊天切换和生成前 token 对比验收。

## 2. 总体方案

采用“脚本内置安装种子 + 酒馆独立世界书 + 注册表驱动控制器”的混合架构。

```text
app 内置 DLC 种子
    │
    ├─ 首次安装 / 恢复默认 / 只补缺失
    ▼
酒馆独立世界书（运行时真源）
    │
    ├─ 角色附属世界书绑定
    ▼
ExpansionManager
    ├─ 安装与兼容诊断
    ├─ MVU 地点/境界判定
    ├─ 用户总开关
    ├─ 条目差异更新
    └─ token 状态摘要
```

脚本内置副本不是运行时正文真源。安装完成后，实际读取和控制酒馆中的独立世界书。用户手动导入新版后，只要世界书身份仍可识别，控制器应继续使用新版内容。

### 3.2 数据所有权

| 数据 | 真源 | 更新规则 |
| --- | --- | --- |
| 世界书正文 | 酒馆中的独立世界书 | 用户可手动导入、编辑、替换 |

| 安装/挂载状态 | 每次从酒馆复读 | 不把缓存当真源 |
| 万年仇怨最高进程 | 当前世界书实际激活状态；必要时辅以隐藏本地元数据 | 不写入模型可见变量 |
| 用户正文修改 | 酒馆世界书 | 默认保留，只有明确确认才覆盖 |

### 3.3 内容身份

第一版不得依赖数组下标。受控条目使用：

1. 稳定 DLC ID；
2. 条目规范名称；
3. 旧名称别名；
4. 内容摘要哈希，仅用于识别内置版、用户修改版和冲突，不作为运行时启停主键。

以后若允许修改世界书格式，可加入默认禁用、不会注入模型的清单元数据条目；第一版不得假设现有 JSON 已携带该元数据。

## 4. 安装、挂载与更新策略

### 4.1 一键安装

“一键安装缺失 DLC”按以下顺序执行：

1. 获取当前世界书名称列表；
2. 按推荐名称和别名识别已安装世界书；
3. 对已存在世界书只读诊断，不写正文；
4. 只创建缺失世界书；
5. 写入对应内置种子条目；
6. 重新读取世界书，核对条目数量和必需条目；
7. 返回逐本结果，不因一本失败而虚报三本全部成功；
8. 安装后重新检测当前角色附属绑定。

重复执行必须幂等。

### 4.2 一键挂载

实现前设置独立 API 真机门：

- 探测当前 SillyTavern、Tavern Helper / JS-Slash-Runner 版本；
- 确认是否存在公开的“写入当前角色 additional worldbooks”接口；
- 确认脚本 iframe 中的可用性、参数、持久化范围和保存行为；
- 调用后必须通过 `getCharWorldbookNames('current')` 复读确认；
- 验证不改变 `primary` 主世界书。

分支策略：

- **公开接口验证通过**：显示“一键挂载到当前角色”；只向 `additional` 追加缺失 DLC，保留已有附属世界书和主世界书；
- **没有公开接口或验证失败**：不调用私有替代方案；显示“复制待挂载名称”和清晰的一次手动挂载指引。

### 4.3 手动更新

用户可在酒馆中独立替换任一本世界书。控制器随后重新诊断：

- 名称与必需条目兼容：继续使用；
- 正文哈希变化：标记“用户修改版”，不覆盖；
- 新增未知条目：保留，提示尚未纳入自动控制；
- 条目改名：先查别名，仍不匹配则标记兼容警告；
- 必需条目缺失或重名：停止自动写该本世界书，防止误改。

可提供三种显式维护操作：

- `只补缺失`：推荐，只添加确实缺失的内置条目；
- `查看差异`：显示新增、缺失、正文变化和名称冲突摘要；
- `恢复内置版`：破坏性覆盖，必须单本选择并二次确认，禁止“一键覆盖全部”。

## 5. 统一运行时控制

### 5.1 触发链

主触发点：

1. 脚本启动且 Tavern Helper、MVU 就绪；
2. `Mvu.events.VARIABLE_INITIALIZED`；
3. `Mvu.events.VARIABLE_UPDATE_ENDED`；
4. `CHAT_CHANGED`；
5. 用户保存 DLC 开关；
6. 安装、挂载或手动兼容检查完成。

生成前保险检查必须先验证目标运行时的世界书扫描时序。若不能证明能在扫描前完成写入，则不把它作为主正确性来源，只作为诊断或下一轮收敛保护。

### 5.2 并发与生命周期

- 使用单例 `ExpansionManager`；
- 脚本重新载入前销毁旧实例；
- 事件进入短防抖队列，合并同一回复造成的重复通知；
- 同一时刻只允许一次世界书事务；
- 新请求到达时记录一次待重跑，不并发覆盖；
- 世界书状态只有写入后复读成功才进入缓存；
- 聊天切换使旧异步任务失效，禁止旧聊天结果写入新聊天；
- `pagehide` / `destroy()` 清理监听、计时器和全局引用。

### 5.3 开关语义

第一版使用布尔开关，默认关闭：

- 关闭：停止该 DLC 自动控制，并关闭该 DLC 受控注入条目；不删除世界书、不解除挂载、不清除进度；
- 开启：允许按地点或境界自动控制；不是强制打开全部条目。

后续若有真实需求，再增加“自动 / 强制开启 / 关闭”三态；第一版不提前增加复杂度。

## 6. 每轮 token 优化

### 6.1 条目分层

每本世界书将条目登记为：

- `core`：满足条件时必须常驻的最小规则；
- `detail`：启用但依赖关键词命中，通常不占每轮 token；
- `stage`：剧情进程互斥条目；
- `unmanaged`：保留原状态，不由脚本改动。

优化重点是 `constant=true` 或等价常驻条目。不得把“启用的关键词条目”误算成每轮必然注入。

### 6.2 四本 DLC 策略

#### 洛阳

- 不在洛阳或总开关关闭：关闭所有受控洛阳条目；
- 在洛阳：只常驻洛阳总览和确有必要的短规则；
- 节日、机构、区域、学宫等尽量使用关键词详情；
- 修复原助手“游仙学宫 / 仙游学宫”名称错误，但不执行原助手。

#### 合欢宗·百花谷

- 合欢宗通用设定与百花谷地点内容分组；
- 不在百花谷时关闭地点、设施、物价、任务和活动常驻内容；
- 人物、设施和改造详情依靠关键词触发；
- 禁止复刻原助手的一秒轮询。

#### 万年仇怨

- 按 `stat_data.主角.境界` 计算目标最高进程；
- 五个进程始终最多激活一个；
- 进程只上升不下降；
- 已解锁怪物和机关可保持关键词可触发，但不转为常驻；
- 总开关关闭只停止注入，不抹除已经达到的最高进程。

#### 蜀山剑门

- 使用 `shushan-hybrid` 混合策略，不照搬洛阳的整本地点全开；
- 离开蜀山时关闭宗门总览、叙事基调、课程、部门、年度事件和各峰总览等基础常驻条目；
- 人物、场所、互动和每日事件等非恒定条目保留原生关键词扫描能力；
- 进入蜀山范围时启用基础条目；进入飞霜峰、镇岳峰、凌虚峰、抱朴峰、冲霄峰或无我峰时，只启用对应峰脉详情；
- 蜀山范围识别包括蜀山、六峰、青石坊和锁妖塔；总开关关闭时全部关闭。

### 6.3 token 证据

为三种场景记录生成前世界书激活摘要和提示词 token 对比：

1. 三个 DLC 全关；
2. 仅当前地点 DLC 自动开启；
3. 四个 DLC 粗暴全开对照组。

验收报告至少给出常驻条目数、实际激活条目数、注入字符数和目标运行时可取得的 token 计数。不得只用文件大小宣称节省成功。

## 8. BridgeAction 草案

只开放具体动作，不开放通用世界书写入接口：

- `REQUEST_DLC_STATUS`
- `DLC_STATUS_DATA`
- `INSTALL_MISSING_DLCS`
- `DLC_INSTALL_STATUS`
- `ATTACH_DLCS_TO_CURRENT_CHARACTER`
- `DLC_ATTACH_STATUS`
- `SAVE_DLC_SETTINGS`
- `DLC_SETTINGS_STATUS`
- `CHECK_DLC_COMPATIBILITY`
- `DLC_COMPATIBILITY_DATA`
- `REPAIR_DLC_MISSING_ENTRIES`
- `DLC_REPAIR_STATUS`

“恢复内置版”不进入第一批默认动作；只有差异查看、备份和二次确认方案完成后再增加。

## 10. 自动测试矩阵

### 安装与更新

- 无世界书时安装三本；
- 已有一本时只安装另外两本；
- 同名重复候选时阻断；
- 重复点击安装不重复；
- 用户修改正文后重启不覆盖；
- 缺失条目只补缺失；
- 条目改名、重名和新增未知条目正确诊断。

### 自动控制

- 空 MVU 安全降级；
- 进入/离开洛阳；
- 进入/离开百花谷；
- 地点长字符串包含目标地点；
- 筑基至渡劫逐级提升；
- 高境界直接开局；
- 境界下降不回退万年仇怨进程；
- 用户关闭开关优先于自动条件；
