# 道渊小手机 V1.5 Vue/UI 重构实施计划

> 状态：规划中，作为 V0.7 的并行开发线
> 目标：在不破坏 V0.7 正式版本的前提下，将 iframe 内前端逐步迁移为 Vue 组件化界面，并完成手机/桌面平板双布局。

实施进度见：[实施进度](实施进度.md)。每个阶段必须在进度台账中记录状态、验证证据和下一步，再进入下一阶段。

## 1. 版本与分支定位

```text
V0.7：当前稳定版本，继续维护和修复
V0.8～V1.0：现有架构上的功能迭代
V1.5：Vue + UI skill 重构线
```

建议分支名：`refactor/v1.5-vue-ui`

V1.5 分支从 V0.7 正式源码建立，独立构建、独立打包、独立验证。未完成验收前，不覆盖 V0.7 正式 JSON，也不要求 V0.7 合并任何 Vue 代码。

## 2. 保持不变的边界

V1.5 首阶段只重构 iframe 内 UI，不重写宿主运行时。

保留以下协议和职责：

- `src/index.ts` 的 Tavern Helper 生命周期、桌宠、iframe 和上下文管理；
- `src/contract/bridge.ts` 的 BridgeAction 与 payload 契约；
- `src/contract/appData.ts` 的数据 schema 和聊天变量键；
- `src/services/` 的 MVU 读取、聊天变量、API、世界书和提示词注入服务；
- V0.7 的数据所有权：绝色榜、风闻、论坛、日报等独立数据不迁移回 MVU；
- V0.7 的正式 JSON 导入方式。

Vue 组件禁止直接调用 `Mvu`、`fetch`、Tavern Helper 或宿主页面 DOM，所有宿主能力必须经过 bridge client。

## 3. 目标架构

```text
SillyTavern / Tavern Helper
        │
        ▼
FeatureShell（宿主层）
生命周期、MVU、聊天变量、API、持久化、iframe
        │ BridgeAction
        ▼
Vue App（iframe 内）
路由、页面、组件、表单、弹窗、响应式布局
```

建议目录：

```text
src/ui/
  App.vue
  appStore.ts
  bridgeClient.ts
  router.ts
  tokens.css
  components/
  pages/
```

初期使用轻量 store（`shallowReactive` + composable）即可；当跨页面状态继续增长，再评估引入 Pinia，避免为了迁移 UI 额外扩大正式产物。

## 4. 双布局目标

### 4.1 宿主外壳层

由宿主负责悬浮球、浮窗/抽屉、iframe 尺寸、位置、软键盘和可视区域。

```ts
type LayoutMode = 'auto' | 'desktop-tablet' | 'phone'
```

自动模式使用滞回断点，避免窗口在临界宽度抖动：

- 宽度 ≤ 680px：进入手机布局；
- 宽度 ≥ 760px：返回桌面平板布局；
- 中间区域保持当前布局。

桌面内容区保持 16:9，按可用空间计算：

```text
width = min(maxWidth, availableWidth, availableHeight × 16 / 9)
```

### 4.2 Vue 内容层

Vue 负责页面内部的：

- 手机单列导航；
- 桌面平板双栏或宽屏卡片布局；
- 页面内抽屉、弹窗和详情页；
- 内容密度、文本换行和滚动；
- 当前 App、选中项、草稿和未读状态保持。

布局切换不得重建 store、重复订阅或重复请求。

## 5. 分阶段实施

### 阶段 0：基线冻结与分支准备

- 从 V0.7 正式源码建立 V1.5 分支；
- 记录 V0.7 构建产物、JSON 哈希和当前测试结果；
- 确认正式源码只以 `道渊前端桌宠/integration/tavern-helper-pet/` 为准；
- 建立 Vue 分支专用产物名，例如 `道渊小手机V1.5-preview.json`；
- 明确 V0.7 回滚方式。

验收：V0.7 分支仍可独立构建、打包和导入。

### 阶段 1：Vue 壳与 Bridge client

- 在 iframe 中使用 `createApp(App)` 挂载 Vue；
- 建立 `bridgeClient`，统一发送和接收 BridgeAction；
- 将 `REQUEST_CONTEXT` 转为 Vue store 初始状态；
- 处理 iframe load、app ready、销毁和 `app.unmount()`；
- 先实现页面壳、顶部栏、底部导航、加载态、错误态和空态。

验收：不改变业务功能，重复打开/关闭不产生重复监听或重复实例。

### 阶段 2：公共视觉与交互系统

- 建立语义化颜色 token、字体层级和 4/8px 间距系统；
- 统一按钮、卡片、列表、标签、弹窗和表单控件；
- 使用一致的 SVG 图标，不使用 Emoji 作为结构性图标；
- 触控区域目标不小于 44px；
- 支持键盘焦点、动态 aria 属性、错误提示和 reduced-motion；
- 保持现有暗色、金色、青玉色的道渊视觉，不直接采用 UI skill 自动生成的赛博青色方案。

### 阶段 3：低风险页面迁移

按以下顺序迁移：

1. 设置；
2. 储物袋；
3. 地图；
4. 绝色榜；
5. 仙网风闻；
6. 仙网论坛；
7. 天机日报；
8. 玉简传讯。

每迁移一个页面，保留旧页面作为临时对照，完成类型检查、fixture 检查、桌面/手机检查后再删除旧实现。

### 阶段 4：外壳与双布局

- 增加 `auto / desktop-tablet / phone` 模式；
- 实现电脑 16:9 宽屏（模拟平板）；
- 实现手机单列 UI、安全区、横屏和软键盘适配；
- 监听 `ResizeObserver`、`visualViewport` 和设备旋转；
- 跨断点保留路由、选中项、表单草稿、未读状态、滚动和焦点。

### 阶段 5：完整回归与 V1.5 预览包

- 运行类型检查、fixture 检查、页面静态验证和生产构建；
- 生成 V1.5 独立测试 JSON；
- 在真实 SillyTavern 中验证导入、聊天切换、swipe、重载、关闭和销毁；
- 记录已知限制、正式产物哈希和回滚方式。

## 6. 验收矩阵

### 功能

- V0.7 已有功能在 V1.5 中行为一致；
- BridgeAction 名称和 payload 未被无计划改变；
- 无新增 MVU 写入；
- 独立数据仍保存在原有 chat 变量；
- API、世界书、提示词注入和错误状态可用。

### 设备与布局

- 手机：320×568、360×800、390×844、430×932；
- 桌面：1920×1080、1366×768、约 900×600；
- 手机横屏、软键盘、200% 缩放；
- 自动布局往返切换不丢状态、不重复请求；
- 不出现横向溢出，长中文和长 URL 可换行。

### 质量与可访问性

- 主要文字对比度至少 4.5:1；
- 所有控件有可见名称或 aria-label；
- 所有点击控件有 pressed/focus 状态；
- 交互动画约 150～300ms，并支持 reduced-motion；
- 固定头部和底部导航不会遮挡滚动内容。

## 7. 回滚与合并规则

- V0.7 始终保留可发布分支和正式 JSON；
- V1.5 只发布带 `preview` 标识的测试产物，直到完整验收；
- 任一阶段出现数据写错、重复实例、Bridge 回归或真实酒馆异常，暂停迁移并回退该阶段；
- 不直接修改已打包 JSON，所有修复从源码重新构建；
- V1.5 验收通过后，再单独评审是否合并到下一正式版本，不自动回写 V0.7。

## 8. 完成定义

V1.5 只有在以下条件同时满足时才算完成：

- Vue UI 已替换目标页面；
- 宿主协议、数据所有权和 MVU 边界保持不变；
- 手机与桌面 16:9 平板布局均通过真实酒馆验证；
- 构建、打包、导入和回归测试针对同一 V1.5 产物通过；
- V0.7 仍可独立构建和发布；
- 已记录产物哈希、已知限制和回滚方式。
