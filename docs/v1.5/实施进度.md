- [ ] 完整回归：聊天切换、长时间运行、Bridge 异常消息和 V0.7 正式包回归。

**当前判断**：阶段 1 启动层阻塞已解除；剩余为完整回归项，不阻塞进入阶段 2。

**追加排查**：V1.5 预览包此前复用了 V0.7 的 Tavern Helper 自定义脚本 ID `daoyuan-feature-frontend-hud`，存在同 ID 注册冲突风险；已改为 `daoyuan-feature-frontend-hud-v15` 并完成重新构建，待重新导入酒馆复测。

**第二轮修复**：启动入口不再依赖 Tavern Helper 全局 `$` 的 ready 队列；脚本 iframe 在非 loading 状态直接启动，并对 `FeatureShell.start()` 增加启动异常日志。这样可区分“生命周期未触发”和“启动阶段抛错”。

**开发文档核对**：已读取本机 JS-Slash-Runner 4.9.1 源码。角色脚本确实通过隐藏 iframe 的 `<script type="module">` 执行，`predefine.js` 将 TavernHelper/MVU 等绑定注入 iframe；V1.5 运行时 iframe 可在 `Page.getFrameTree` 中看到，但该脚本日志为空。当前新增 `boot entry` 日志用于确认模块正文是否真正进入启动函数。

**根因确认**：Vue 运行时保留了 `process.env.NODE_ENV`，而 Tavern Helper 脚本 iframe 是纯浏览器环境，没有 Node `process`，因此在进入 `boot` 前抛出 `ReferenceError: process is not defined`。已在 Vite 生产构建中注入 `process.env.NODE_ENV = "production"`；重新构建后产物不再包含 `process.env`，并通过无 Node 全局的离线执行探针越过该异常。
