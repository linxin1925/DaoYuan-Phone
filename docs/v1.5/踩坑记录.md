# V1.5 踩坑记录

## 2026-08-12：Vue 运行时导致桌宠完全不显示

### 现象

- V1.5 角色脚本在酒馆脚本列表中可见，但桌宠、HUD 和 Vue 页面均不出现。
- Tavern Helper 日志查看器没有 V1.5 的 `boot entry` 或 `phone-ratio shell ready` 日志。
- V0.7 仍可正常运行，问题只出现在引入 Vue 的 V1.5 构建。

### 排查过程

1. 确认不是 Vue 挂载阶段：桌宠节点是在 `FeatureShell.start()` 早期创建的，连桌宠节点都没有，说明故障早于 UI 挂载。
2. 按本机 JS-Slash-Runner 源码核对脚本机制：角色脚本通过隐藏 iframe 的 `<script type="module">` 执行。
3. 读取本机脚本 iframe 的错误上下文，发现构建产物包含 Vue 的 `process.env.NODE_ENV`。
4. 浏览器 iframe 没有 Node 的 `process` 全局，因此在 Vue 运行时初始化阶段抛出：

   `ReferenceError: process is not defined`

### 根因

Vite library build 将 Vue runtime 打入 Tavern Helper 的浏览器脚本，但没有替换 Vue runtime 使用的 `process.env.NODE_ENV`。脚本在进入 `boot()` 前就异常终止，所以不会产生任何业务日志。

### 修复

在 `vite.config.ts` 的生产构建中加入：

```ts
define: {
  'process.env.NODE_ENV': JSON.stringify('production'),
}
```

重新构建后，产物不再包含 `process.env` 引用，V1.5 桌宠和手机 UI 恢复显示。

### 预防规则

- 任何新增前端依赖都必须检查最终 IIFE 是否引用 Node-only 全局：`process`、`Buffer`、`global` 等。
- 必须在“无 Node 全局”的浏览器环境做一次构建产物探针。
- “没有桌宠”先按启动阶段分层：脚本未执行 → 运行时异常 → `FeatureShell.start()` → 宿主节点 → iframe/Vue 挂载。
- 不要先修改 Vue 组件或 CSS 来处理启动层故障。
