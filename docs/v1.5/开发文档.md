# 道渊小手机 V1.5 开发文档

## 1. 运行边界

V1.5 是 Tavern Helper 角色脚本，不是独立网页应用。酒馆助手会为启用的角色脚本创建隐藏 iframe，并以如下形式执行脚本内容：

```html
<script type="module">
  <!-- 构建后的 IIFE 内容 -->
</script>
```

本机 JS-Slash-Runner 4.9.1 的 `predefine.js` 会向脚本 iframe 注入 TavernHelper、SillyTavern、MVU 等宿主能力。脚本需要通过 `window.parent` 访问宿主页面 DOM；可见桌宠不能挂在脚本 iframe 自身。

## 2. V1.5 启动链

```text
角色脚本 iframe
  → boot()
  → FeatureShell.start()
  → 解析宿主 window/document
  → 创建 #daoyuan-feature-orb
  → 点击桌宠后创建 #daoyuan-feature-hud iframe
  → 挂载 Vue App 与兼容旧 UI
```

因此，启动日志和桌宠节点是 Vue 页面验收之前的必要信号。

## 3. 构建约束

- 入口：`道渊前端桌宠/integration/tavern-helper-pet/src/index.ts`
- 构建格式：Vite library IIFE，内联动态导入。
- Vue 通过 `@vitejs/plugin-vue` 编译并随脚本打包。
- 生产构建必须替换 Vue runtime 的 Node 环境判断：

  ```ts
  define: {
    'process.env.NODE_ENV': JSON.stringify('production'),
  }
  ```

- 发布前检查：

  ```bash
  vite build
  node scripts/package-candidate.mjs
  ```

  并确认最终包不含 `process.env`、`require(`、`import.meta` 等不应出现在浏览器脚本中的构造。

## 4. 包装与脚本身份

- V0.7 正式包：`道渊小手机V0.7.json`
- V1.5 预览包：`道渊小手机V1.5-preview.json`
- V1.5 使用独立脚本 ID：`daoyuan-feature-frontend-hud-v15`
- 不覆盖 V0.7 正式包；两者可在同一角色脚本环境并行存在。

## 5. 最小验收顺序

1. 脚本 iframe 存在。
2. 日志出现 `[道渊玉简] boot entry`。
3. 日志出现 `phone-ratio shell ready`。
4. 宿主页面存在 `#daoyuan-feature-orb`。
5. 点击桌宠后出现 HUD iframe。
6. HUD iframe 内 Vue 壳挂载并能发送 `APP_READY`、`REQUEST_CONTEXT`。
7. 关闭 HUD 后 iframe 和 Vue mount 正确销毁。

若第 2 步之前失败，禁止从 Vue 组件、响应式 store 或 CSS 开始排查。
