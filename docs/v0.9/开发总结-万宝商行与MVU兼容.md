## 3. 万宝商行功能范围

万宝商行包含两个数据源完全不同的页面：

1. **万宝货单**：AI 生成，只用于购买；商品来自世界书物价体系和境界规则。
2. **我的物品**：读取玩家真实 `stat_data.主角.储物袋` 与 `stat_data.主角.器物`，只允许出售这两处物品。

边界：商行不得修改状态栏脚本，不得修改主角其他字段，不得把普通 AI 商品直接写入人物、世界、功法以外的系统字段。

## 4. 真实 MVU 写回契约

交易写回入口：`src/services/merchantCore.ts` 的 `applyMerchantTrade`。

购买目标必须按商品类别路由：

```js
主角.储物袋[商品名] // 丹药、材料、符箓、阵盘、杂物等
主角.器物[商品名]   // 器物、法器、法宝、古宝、灵宝等
主角.功法[商品名]   // 功法、心法、武技、秘术等
```

三类条目均必须有：

```js
{
  数量: number,
  描述: string
}
```

货单顶层 `description` 是玩家条目的正文描述来源。战斗属性中的简写描述不得覆盖 `描述`。

出售只读取：

```js
stat_data.主角.储物袋
stat_data.主角.器物
```

灵石不可作为普通物品出售。购买/出售后只更新对应灵石结构、储物袋、器物、功法和商行本地交易记录。

## 5. 原版卡与战斗版灵石

商行支持两种结构：

- 原版：灵石可能混在 `主角.储物袋` 中，与其他物品同级。
- 战斗版：灵石在 `主角` 下独立字段，储物袋中另有物品。

结构模式支持自动识别和手动切换。自动识别只能选择候选，不能改造原版卡的数据结构。

## 6. 战斗版功法结构

V0.7 状态栏实际显示的功法格式来自 `stat_data.主角.功法`。状态栏不是把 `品阶` 单独渲染成标签，而是直接读取 `类型` 字段。

典型结构：

```js
主角.功法.七星剑法 = {
  类型: "天阶-星辰系强攻杀伐",
  本源: "异种-星辰",
  品阶: "天阶",
  效果类型: "强攻杀伐",
  主维: "攻伐",
  辅维: ["遁速"],
  境界: "入门",
  熟练度: 0,
  描述: "...",
  技能: {
    技能名: {
      类型: "攻击/防御/辅助",
      描述: "..."
    }
  }
}
```

兼容要求：

- `类型` 必须生成组合展示格式：`品阶-本源系效果类型`，例如 `天阶-星辰系强攻杀伐`。
- `品阶`、`本源`、`效果类型` 仍需独立保存，供战斗脚本计算。
- `技能` 必须是对象映射，不是字符串数组。
- 技能数量必须按 V0.7 规则：凡阶 1；黄阶 1～2；玄阶 2；地阶 2～3；天阶 3。
- 技能描述不得包含五维数值或替代脚本结算公式。

当前商行在 `merchantRuntime.ts` 的归一化阶段已经对技能数量做硬校验；不符合数量的功法会被丢弃，不得进入货单。

## 7. 战斗版器物结构

战斗版器物写入 `主角.器物`，字段以 V0.7 条目 227 和战斗脚本为准：

```js
{
  数量: 1,
  等级: "法宝/古宝/通天灵宝/先天灵宝/...",
  类型: "攻伐/防御/遁行/神魂/威压/...",
  本源: "五行-火/异种-星辰/概念-空间/...",
  品阶: "凡阶/黄阶/玄阶/地阶/天阶",
  主维: "攻伐/御守/遁速/神魂/灵压",
  辅维: [],
  祭炼度: 0,
  损耗度: 0,
  状态: "正常" 或 "可用",
  描述: "至少 30 字"
}
```

注意：`完好` 不是 V0.7 允许的规范状态。商行会把 AI 返回的 `完好` 归一化为 `正常`；不可用、已损毁、被毁、封印、失效的器物不计入五维。

## 8. 状态栏兼容结论

V0.7 状态栏读取：

- 功法：名称、`类型`、`境界`、`熟练度`、`描述`、`技能`。
- 器物：名称、类型/等级、`描述`及状态相关字段。
- 五维和技能消耗：由 V0.7 战斗脚本根据完整 `stat_data` 计算，商行不得复制战斗公式。

因此，商行必须写入状态栏既有字段，而不能只写商行自己的 `combatData` 结构。

## 9. AI 生成约束

战斗版生成提示词必须包含：

- 只生成主角当前境界及以上、渡劫以上不生成的商品。
- 激活战斗世界书中的境界和灵石物价体系。
- 功法技能数量按品阶严格生成。
- 功法和器物才允许填写战斗属性。
- 丹药、材料、符箓、阵盘、储物袋不得填写战斗五维或技能。
- 器物状态只能写 `正常` 或 `可用`，禁止 `完好`。
- 商品正文描述至少 30 字。
- 商品名不得与现有货单重复。

AI 返回仍必须经过本地 JSON 解析、类别校验、品阶校验、境界覆盖校验、物价校验、战斗字段校验和技能数量校验。

## 11. 已知边界与审查重点

1. 已导入旧 JSON 的旧商品不会自动迁移；测试修复必须重新导入 V0.9 JSON，并重新生成/购买商品。
2. 状态栏刷新依赖酒馆当前运行时接口；若接口不可用，交易写回可能成功但需要手动刷新楼层。
3. 当前实现不能修改 V0.7 状态栏本身；“状态栏是否展示某字段”与“商行是否正确写回字段”必须分开审查。
4. AI 输出不可信，最终以本地归一化和硬校验为准。
5. 不得为修复商行而复制战斗脚本的五维公式。
6. 不得把 `描述`、`特效`、`技能描述` 混为同一字段。
7. 检查任何新字段前，必须先验证真实当前楼层 `stat_data`、MVU-ZOD 和状态栏读取逻辑。

## 13. 交付前验收顺序

1. 先做源码静态审查和类型检查。
