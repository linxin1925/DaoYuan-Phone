# 道渊双界世界推演规则设计

> 状态：评审稿
> 适用范围：道渊小手机的玄天界推演与灵力复苏地球推演
> 本文只定义世界如何运行，不预写任何一局必然发生的剧情。
>
> 当前实施范围：优先完成世界时间、事件因果、势力决策、长期跳时、账本提交与 EJS 路由。数据库接入及 NPC 后台行为持久化暂不进入本阶段。

## 一、共同原则

### 1. 世界自治

- 世界不会因为玩家没有参与而暂停。
- 地域、势力、组织和事件依据自身目标、资源、约束与时间继续演化。
- 玩家是世界中的行动者之一，不是所有事件的默认原因、目标或观察中心。
- 最近正文只能提供已经确认的外部事实，不能取代世界书与世界账本。
- 不得为了让玩家有参与感，强行把远方事件迁移到玩家所在地。

### 2. 双层视角

推演系统同时维护两类信息：

1. **上帝视角世界账本**：保存所有已经确认的客观事实，包括秘密行动、远方事件和玩家尚未知晓的结果。
2. **角色可知信息**：只保存某个角色、势力或玩家通过亲历、通信、调查、媒体、情报网络等渠道能够得知的内容。

后台事实不等于正文角色知道。主对话不得直接读取完整上帝视角账本，只能读取经过可知性过滤的投影。

### 3. 时间权威

- 回复轮数不等于世界时间。
- 世界时间优先从连续两次已确认的 MVU 时间中计算。
- 推演 API 不得自行决定实际过去了多少时间，只能在已确定的时间跨度内推演变化。
- 无法可靠解析时间时停止自动计时，记录诊断并等待玩家校准，不得猜测。
- 重抽、重生成、删楼、回滚、失败回复和中止回复不得重复推进时间。

### 4. 状态权威

- 世界书定义世界事实、运行规律与允许的可能性。
- 当前聊天的推演账本定义这一局已经实际发生的历史。
- API 只返回候选变化，本地脚本负责校验并原子提交。
- 未通过本地校验的候选不得部分写入。
- 玩家计划、猜测、梦境、传闻和模型自行补充的内容不得直接成为客观事实。

### 5. 事件因果

事件必须具有：

- 起因；
- 参与者与各自目标；
- 推动力；
- 阻碍；
- 资源与能力条件；
- 升级条件；
- 停滞、失败、转向和结束条件；
- 影响范围；
- 信息可见范围；
- 可追溯的历史节点。

事件进度不能仅按时间线性增长。没有驱动力的事件应停滞或结束；受到强阻力时可以倒退、转向或长期僵持。

### 6. API 调用

- 普通短时间对话可以按有效回复间隔节流。
- 明确的大跨度时间变化应立即触发，不等待回复计数达到阈值。
- 一次时间跳跃中，每个开启的世界通常只调用一次 API。
- 长时间跨度采用历史压缩和关键节点结算，不按天反复调用 API。
- 失败后重试次数由玩家设置为 0～2 次；单次推演最多请求 1～3 次。
- 鉴权、配置、世界书缺失、前置条件缺失和越权候选不重试。
- JSON/结构错误、限流和服务端错误可在设置上限内重试。
- UI 必须显示调用上限、本次实际请求次数、失败原因及账本是否发生变化。

### 7. EJS 按需装载总则

世界书不得依靠“整本常驻”参与生成。EJS 只负责在酒馆生成提示词前，根据当前世界、地域、势力、事件与角色可知范围，装载本轮确实需要的条目。

必须区分两条上下文链路：

1. **主对话链路**：EJS 将经过可知性过滤的世界信息注入主对话，不得装载完整上帝账本。
2. **后台推演链路**：推演脚本读取与 EJS 相同的路由清单，单独组装 API 请求所需的客观世界规则与账本摘要。EJS 本身不会自动减少后台 API 的输入 Token。

世界书按以下层级拆分：

| 层级 | 内容 | 装载规则 |
| --- | --- | --- |
| L0 路由核 | 条目索引、稳定 ID、依赖关系、预算与回退规则 | 常驻，但必须极小 |
| L1 世界骨架 | 时间、阶段、基础法则、全局约束 | 当前世界开启时装载 |
| L2 区域资料 | 地域、国家、城市、交通与环境 | 只装载当前或事件涉及区域 |
| L3 行动者资料 | 势力、组织、关键人物及能力边界 | 只装载本轮行动者与直接关联者 |
| L4 机制规则 | 科研、战争、贸易、舆论、秘境等事件母题 | 只装载本轮实际使用的机制 |
| L5 历史投影 | 已结事件摘要、当前事件节点、角色可知信息 | 按账本生成，不从整本历史回灌 |

EJS 路由必须遵守：

- 只有少量路由条目使用 `@@generate_before` 与 `@@always_enabled`；资料正文保持关闭或不常驻，由路由通过精确条目名读取。
- 优先使用稳定 ID 和明确清单调用 `getwi`，不以模糊关键词扫描整本世界书。
- 去重后按固定顺序注入；空条目、重复条目和未通过权限过滤的条目不得输出。
- 路由条目应自包含关键默认值，不能依赖多个 EJS 条目的偶然执行顺序。
- 路由状态就绪后，不再重复扫描最近聊天；仅在状态缺失时进行一次有上限的兼容回退。
- EJS 只读取、筛选和输出提示词，不调用推演 API，不直接写入客观账本。
- 条目缺失、世界书改名或 EJS 执行失败时降级为最小世界骨架，并向 UI 写入诊断；不得退化为整本注入。

建议把预算同时定义为“条目数上限”和“估算 Token 上限”。初始默认值可设为：主对话世界书投影不超过 2,500 Token，单世界后台推演资料不超过 6,000 Token；长期跳时可临时放宽至 10,000 Token，但必须优先压缩历史，而不是增加常驻条目。最终数值应以真实酒馆提示词统计校准。

## 二、玄天界推演规则

### 1. 权威来源

玄天界使用独立的《道渊·玄天界世界推演规则书》作为运行规则权威，由小手机内嵌种子并提供安装、挂载、补缺和版本诊断。

权威顺序：

1. 当前角色卡主世界书中明确写明的版本事实；
2. 玩家修改的玄天界推演规则；
3. 玄天界推演规则书的官方默认规则；
4. 当前聊天已确认的推演账本。

当当前角色卡与推演规则书的基础事实冲突时，以当前角色卡为准并记录诊断；运行方法与事件边界仍以玩家规则和推演规则书为准。

推演规则书不得作为普通主线世界书整本注入，避免主对话获得上帝视角信息。

### 2. 世界结构

玄天界至少维护以下客观层级：

- 五大地域及跨域空间；
- 宗门、皇朝、妖族、商会、散修组织等势力；
- 灵脉、矿产、药材、人口、商路、传承、秘境等资源；
- 地域间交通、信息传播和补给成本；
- 高阶修士、护山大阵、盟约和禁地等威慑力量；
- 天象、灵潮、秘境、兽潮与灾害周期；
- 公开秩序与秘密行动。

### 3. 地域运行

每个地域应定义：

- 核心资源；
- 长期矛盾；
- 稳定力量；
- 地理与交通限制；
- 周期性变化；
- 外部依赖；
- 主要势力；
- 可产生的事件母题；
- 当前压力与恢复能力。

地域变化不能只表现为战争。可出现贸易变化、迁徙、建设、人才流动、技术扩散、宗教活动、生态改变、外交与社会秩序变化。

### 4. 势力自治

每个主要势力至少具有：

- 长期目标；
- 当前目标；
- 核心需求；
- 核心恐惧；
- 可调用资源；
- 行动限制；
- 决策风格；
- 对外关系；
- 内部派系与分歧；
- 升级条件；
- 妥协与撤退条件；
- 信息获取能力；
- 对普通成员与统治区域的责任。

势力行动必须符合自身能力和认知。势力不知道的事情不能影响其决策；资源不足、路途遥远或高阶威慑存在时，行动规模必须受到限制。

### 5. 强者与组织的关系

- 高阶修士是重要威慑，但不能替代人口、后勤、情报、制度与基层执行。
- 大能可以改变局部力量平衡，但不能无成本地同时处理所有地域问题。
- 势力不得因为拥有高阶修士就自动全知、永远正确或内部一致。
- 高阶修士长期闭关、受伤、立场变化或不愿干涉时，组织行为必须相应改变。

### 6. 玄天界事件母题

事件池应覆盖但不限于：

- 资源开发与贸易竞争；
- 宗门内部路线斗争；
- 皇朝政治、继承与地方治理；
- 外交、联盟、背约与中立协调；
- 功法、炼丹、炼器和阵法突破；
- 人才招募、教育、传承与叛逃；
- 商路、坊市、税赋和运输危机；
- 信仰、戒律和文化冲突；
- 人口迁徙、灾后重建和社会变迁；
- 天象、灵潮、秘境、兽潮和生态变化；
- 情报战、谣言、渗透和秘密调查；
- 执法、审判、复仇和制度冲突；
- 节庆、盛会、交流、建设与长期繁荣。

同一批新事件不得全部属于资源争夺、偷猎或宗门仇杀。事件多样性来自不同社会机制，不只来自名称替换。

### 7. 新聊天开局

每个新聊天生成一个稳定的开局种子，同一聊天保持不变，不同聊天允许形成不同平行历史。

开局种子可包含：

- 主导地域；
- 活跃势力；
- 世界基调；
- 压力主题；
- 偏好事件母题；
- 暂时排除的重复母题；
- 初始烈度；
- 世界总体稳定度。

空账本不再强制立即制造三条冲突。允许以平静、建设、外交、暗中准备或潜在压力开局。

### 8. 事件阶段

推荐阶段：

```text
潜势 → 苗头 → 酝酿 → 发展 → 转折/高潮 → 收束 → 余波
```

规则：

- 阶段通常逐级变化，但长期跳时可以通过多个有记录的历史节点跨越。
- 每个阶段具有最短合理时间、进入条件和退出条件。
- 事件可以进入休眠、僵持、失败或转化为新事件。
- 事件结束后保留摘要和主要后果，不无限保留完整过程。
- 新事件必须能追溯到地域压力、势力目标、周期机制或既有事件后果。

### 9. 长时间跳跃

时间结算建议：

| 跨度 | 推演方式 |
| --- | --- |
| 1～7 日 | 日级或整段结算 |
| 8～90 日 | 旬/月级结算 |
| 3 个月～3 年 | 季度或年度关键点 |
| 3～30 年 | 年代压缩与关键节点 |
| 30 年以上 | 时代摘要、格局变化与遗留问题 |

本地调度器先扫描事件到期点，再将跨度压缩为少量关键节点，一次 API 批量裁决。不得把三十年当作三十天，也不得为三十年逐日调用 API。

### 10. 玩家影响边界

- 玩家私下修炼、交谈、恋爱或闭关不会自动成为天下公开事件。
- 玩家只有在直接参与、公开行动、改变资源流向、影响势力决策或造成可传播后果时，才能改变相关世界状态。
- 未与玩家发生被其知晓的接触时，势力不得改变对玩家关系。
- 玩家可以终止、加速、延缓或转向事件，但不能让无关地域自动围绕玩家变化。
- 推演 API 不得替玩家决定行动、台词、情绪、身份、关系和不可逆选择。

### 11. 玩家可编辑规则

推演世界书应预留：

- 世界基调；
- 推演烈度；
- 活跃与休眠势力；
- 事件母题偏好；
- 禁止事件；
- 伤亡与毁灭尺度；
- 世界变化速度；
- 自定义势力；
- 自定义地域；
- 自定义运行规则。

官方更新只补缺或更新未被玩家修改的官方条目，不得覆盖玩家配置。

### 12. 玄天界 EJS 路由

玄天界推演规则书内嵌一个轻量路由核，但规则正文按地域、势力和事件机制拆成独立条目。建议维护以下路由状态：

- 当前世界与规则书名称；
- 当前地域及最多 1 个直接关联地域；
- 本轮行动势力及最多 4 个直接关联势力；
- 当前事件稳定 ID 及最多 3 类事件机制；
- 玩家可知条目清单；
- 后台推演条目清单；
- 本轮 Token 预算与裁剪记录。

主对话只注入“当前地域骨架 + 当前场景相关势力 + 玩家可知事件投影”。远方秘密、其他地域全貌和势力内部计划只进入后台推演清单。

后台推演的玄天界资料优先级为：

1. 时间、修炼体系与世界硬约束；
2. 到期事件及其直接行动者；
3. 涉及地域、资源、交通和威慑条件；
4. 本轮所需事件机制；
5. 相关历史摘要。

预算不足时，先删除无关人物细节，再压缩旧历史，最后减少低优先级旁支事件；不得删除决定事件是否合法的境界、地理、资源和信息边界。

## 三、地球推演规则

### 1. 权威来源

地球直接使用《灵力复苏地球附属世界书》作为事实与运行规则权威，不另建第二本地球推演书。

权威顺序：

1. 玩家修改的地球世界书条目；
2. 地球世界书的官方事实与运行规则；
3. 当前聊天已确认的地球推演账本；
4. 已确认的玄天界跨界影响。

地球世界书既包含国家、城市、组织、NPC 与超凡规则，也包含独立推演所需的制度、经济、科研、舆论和事件逻辑。

### 2. 世界结构

地球至少维护：

- 国家与地方政府；
- 国际组织与跨国关系；
- 科研机构、大学、医院和超凡学校；
- 军事、警务、应急与情报系统；
- 企业、资本、供应链和基础设施；
- 媒体、社交平台和公众舆论；
- 宗教、民间组织与超凡社群；
- 城市、人口、交通、能源和通信；
- 灵力复苏、相交秘境与虫群三条相互关联但不能混同的通道。

### 3. 现代制度约束

- 国家与组织通过制度、预算、法律、程序和人员执行，不以单个强者意志替代整个系统。
- 政策变化必须考虑信息可信度、行政能力、社会成本与公众反应。
- 科研突破需要样本、实验、复现、安全验证、生产和推广周期。
- 军事行动需要情报、授权、后勤和风险评估。
- 国际变化应考虑主权、联盟、竞争、制裁、合作和信息不对称。
- 基础设施受建设周期、供应链、资金、人才和地区条件约束。

### 4. 国家与组织自治

每个国家或组织至少定义：

- 公共职责；
- 长期战略；
- 当前政策；
- 资源与能力；
- 制度限制；
- 内部部门分歧；
- 公众与利益相关者压力；
- 信息可信度；
- 国际关系；
- 升级、合作、公开和撤退条件。

国家不能因领导人知道某事就视为所有部门同步知晓；政策宣布也不等于基层已经完成执行。

### 5. 灵力复苏阶段

推荐主阶段：

```text
复苏初现 → 局部复苏 → 全球公开 → 全面超凡化
```

阶段推进必须由世界时间和足够的客观事实共同决定，不能靠对话次数刷取。

每个阶段需要分别定义：

- 灵力可测程度；
- 超凡人口规模；
- 政府知情范围；
- 公众知情范围；
- 科研与教育水平；
- 法律和治理状态；
- 产业化程度；
- 灾害应对能力。

### 6. 地球事件母题

事件池应覆盖：

- 异常发现、观测和科学验证；
- 医疗、公共卫生和超凡副作用；
- 教育、学校建设与人才培养；
- 法律、身份、监管和权利争议；
- 产业升级、能源、材料与供应链；
- 城市治理、基础设施与灾害响应；
- 媒体报道、谣言、恐慌和公众沟通；
- 国家竞争与国际合作；
- 军事安全、情报与技术扩散；
- 企业竞争、垄断、投资与劳工问题；
- 宗教、文化、伦理和社会适应；
- 民间超凡组织与地下市场；
- 相交秘境探索与跨界制度建设；
- 虫群迹象、防疫式控制和区域战争风险；
- 日常生活、就业、住房、交通和家庭结构变化。

不得把地球推演缩减成“政府发现异常—建立学校—虫群入侵”三条固定主线。

### 7. 科研与技术扩散

科研事件应遵循：

```text
异常观测 → 提出假设 → 小规模验证 → 独立复现 → 安全评估
→ 工程样机 → 受限应用 → 标准化/产业化
```

- 单次样本不能直接产生全球成熟技术。
- 玄天界功法、丹药或法器进入地球后必须经过兼容性、安全性和可复制性验证。
- 掌握知识不等于具备制造能力；制造成功不等于能规模化供应。
- 技术扩散速度受到保密、专利、政治、伦理、供应链和人才约束。

### 8. 舆论与信息传播

- 秘密机构知情不等于公众知情。
- 传闻、偷拍视频、媒体报道、官方公告和科学共识是不同证据等级。
- 热门讨论不能自动证明事实。
- 信息可以失真、延迟、被压制或被竞争叙事利用。
- 重大公开事件应记录不同群体的反应，而不是让全世界形成单一意见。

### 9. 双界接触

双界接触推荐阶段：

```text
互不知情 → 少数知情 → 势力接触 → 公开交流
```

- 接触阶段必须由可靠证据推进。
- 相交秘境、通信渠道和虫群通道分别记录，不能互相替代。
- 控制相交秘境不能自动关闭虫群通道。
- 私人接触不会自动升级为国家关系。
- 跨界物资、人员与知识流动必须考虑检疫、语言、制度、运输、安全和利益分配。

### 10. NPC 与普通人

- 固定 NPC 使用稳定 ID 持续记录。
- 临时人物只有在重复互动、承担承诺、掌握关键证据或造成长期后果时才进入长期账本。
- NPC 只能依据亲历、权限、调查和可靠情报行动。
- 职位提供资源和职责，不赋予全知能力。
- 世界变化应体现普通人、基层执行者和不同社会群体的适应，不只记录高层会议。

### 11. 长时间跳跃

长期地球推演除事件外，还应结算：

- 人口与超凡者规模；
- 法律与机构成熟度；
- 科研和产业扩散；
- 教育体系与代际变化；
- 城市建设和基础设施；
- 舆论记忆与文化变化；
- 国际格局；
- 已有 NPC 的年龄、职位和人生轨迹。

长时间跨度采用时代节点压缩，不逐日调用。跨越多年时必须留下关键制度、技术和社会转折，不得只修改日期。

### 12. 玩家影响边界

- 玩家在玄天界的私人行为不会自动影响地球。
- 只有跨界通信、人员、物资、公开证据或可观察后果才能成为地球推演输入。
- 玩家提供功法或技术不代表地球立即掌握、接受或普及。
- 玩家可以影响组织选择，但不能替国家、社会和所有普通人统一决定立场。
- 推演不得替玩家承诺合作、公开身份、交出资源或承担政治立场。

### 13. 玩家可编辑规则

地球世界书应预留：

- 复苏速度；
- 世界公开程度；
- 科技与修炼融合速度；
- 国家合作或竞争烈度；
- 灾害与伤亡尺度；
- 虫群压力；
- 社会接受度；
- 偏好与禁止事件；
- 自定义国家、组织、城市和 NPC；
- 自定义地球运行规则。

官方补缺或升级不得覆盖玩家已经修改的正文。

### 14. 地球 EJS 路由

地球沿用现有 `daoyuan_earth` 路由状态，并将国家、组织、学校、城市、NPC、虫群、货币与制度机制分别维护为可选条目。建议默认上限为：国家 2 个、组织 4 个、学校 2 个、城市 3 个、长期 NPC 4 个、事件机制 3 类；达到上限后按事件相关度裁剪，而不是继续堆叠。

主对话只注入“当前地点 + 可接触组织/NPC + 玩家能够获知的公开或私下信息”。国家级秘密、未公开科研、跨国情报与虫群真实态势只进入后台推演清单。

后台推演的地球资料优先级为：

1. 当前复苏阶段、时间与制度硬约束；
2. 到期事件和直接负责机构；
3. 涉及国家、城市、基础设施与供应链；
4. 科研、舆论、法律、军事或灾害等本轮机制；
5. 公众认知、角色可知性与历史摘要。

地球路由不得因为正文出现一个国家名，就自动装载该国全部组织、学校、城市和 NPC。关联条目必须由稳定 ID、事件参与关系或玩家所在场景明确选入。

## 五、待玩家确认

以下内容在实施前需要确定：

1. 玄天界推演规则书的官方事实应覆盖到什么程度：只写五域与势力骨架，还是包含主要角色的跨版本兼容档案。
2. 新聊天是否默认随机生成平行世界种子，还是允许玩家选择“稳定、暗流、动荡、灾变”等开局模板。
3. 玄天界与地球的默认推演烈度。
4. 是否允许事件进度倒退，以及倒退在 UI 中如何展示。
5. 长期跳时中单次最多保留多少个历史节点。
6. 玩家修改官方规则后，更新时采用“只补缺”还是提供逐条差异选择。
7. 上帝账本中秘密事件的保存上限和过期摘要方式。
8. 主对话每轮最多注入多少条玩家可知世界变化。
9. 主对话 2,500 Token、普通推演 6,000 Token、长期推演 10,000 Token 的初始预算是否合适。
10. 玄天界与地球各类条目的默认装载数量是否允许玩家分别覆盖。
11. 路由诊断是否在 UI 中展示本轮已装载条目、估算 Token、被裁剪条目与降级原因。

## 六、后续阶段待办

以下项目须在双界世界推演主链稳定并通过长期跳时测试后再实施：

- 接入 SP·数据库的公开表格 API，并对缺失、未就绪和版本不兼容提供明确降级。
- 将重要 NPC 的当前状态投影写入“重要角色表”。
- 新建独立的 NPC 后台行为记录表，避免把完整行为流水堆入角色状态行。
- 为 NPC、推演批次和行为记录设置稳定 ID，保证 API 重试与回放不会重复写入。
- 建立“候选行为校验 → 世界账本提交 → 角色状态更新 → 行为记录追加”的原子提交顺序。
- 通过 EJS 可知性过滤阻止秘密行动和上帝视角状态泄漏到主对话。

此阶段开始前需重新确认数据库插件的固定版本、运行模式、公开 API 能力和真实酒馆持久化行为；不得仅凭 CDN 脚本存在便宣称兼容。
